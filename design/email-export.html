Email export

"Copy for email" puts the email below on the clipboard (HTML, with a plain-text copy for clients that only take text), then opens the mail client with just the subject filled in; the user pastes. A plain mailto: body can't carry HTML or images and long ones get cut off. Sources are left out.

The control

One envelope button in each answer's action bar (next to Copy), no header button: its dialog also covers the whole conversation. Scope defaults to the answer clicked; "Whole conversation" is hidden in a one-question conversation; the graph checkbox shows only when the chosen part has a graph, which goes in as the view it's showing in the app. The last choices are remembered in this browser. After copying, a toast says to paste (the status line under the thread stands in for it). "Copy only" is for webmail users whose mailto: opens the wrong app, or nothing.

Paste test

Copy, paste into a new message in each mail client, and send it to yourself: some clients keep a pasted image in the draft and drop it on send. "Copy image only" is the fallback if the HTML copy loses the image: a plain picture on the clipboard, which most clients take as an attachment or inline image.

The graphs, as drawn for capture

Drawn by the app's own code in light colours, on white. The recipient's theme can't be known (many read mail in dark mode) and a pasted email can't swap images by theme, so the graph is one image that reads in both: a white figure, like a chart in a document. Force is deterministic: the same graph always gets the same layout, so a graph the user never scrolled to can be drawn off screen and still match.
