Form prefill

bdc-assist#64. An answer that cites a page with a form offers to fill it in. The draft is a card in the conversation: refine it by chatting ("mention I'm on Terra") or by clicking a value and typing, either in the conversation or in a tool view beside it. Open form is an ordinary link to the BDC page with the values as URL parameters, and the user still reviews and submits there.

The flow

Step through with ‹ ›, or use the page as a user would: Prefill form (or the help icon in the header) starts a draft, the composer holds the next scripted message, and in the latest draft you can click any value to edit it. Your edits go with the next message, so the agent builds on them: in step 5 the subject keeps what you typed. Refine in a tool view: Prefill form opens the tool and drafts there, nothing is added to the conversation, and the offer turns into a small card for the draft (always the draft as it is now), and the draft opens in a split beside it with its own chat, so the scripted messages go in the tool's composer and the conversation doesn't grow. No versions: Undo and Redo in the tool's header step back and forward through changes (an unsent edit first), and a changed graph says "Edited since this answer" with Reset to original. Drag the divider (or focus it and use the arrow keys; double-click resets), and hide or show the conversation with the button at the left of the tool's header. Each tool sets how it opens: the form at 40% beside the conversation, a graph at 70% with the conversation hidden (switch Tool view shows to see it, and send its message to expand it). On a narrow window the tool view is full screen.

The link

What Open form in the latest draft opens. Blank fields are left out. Values go in the URL, so they can end up in browser history and the site's logs, which is one reason personal details are optional. Try the link: if the BDC site doesn't read these parameters yet, the form opens empty.

To check

  1. Is the offer under the answer noticeable without being pushy? Which header icon, with its tooltip, best says "exit to the help desk"?
  2. The card's value states: filled; needed (a required field the agent couldn't fill; not in this script, clear Subject to see it); left for you (name and email: fill in on the form); optional, left blank; and consent, which is never prefilled. Plus the updated and edited tags. Too many?
  3. Research community: the agent can't know it unless the user says. Should it ask, or leave it?
  4. Dropdowns edit as dropdowns. Set Type to Publishing Research: the form's extra section (paper title, date, journal, link) appears, with the required title marked needed.
  5. The page asks people not to include controlled data, participant information or credentials. The agent should follow that when drafting; should the card also say it?
  6. Conversation mode: prefill request as a status line or as a user message? The user message shows what the agent was asked; the line keeps the thread to the user's own words.
  7. Older drafts collapsed or kept greyed? (Conversation mode only: the tool view has Undo instead.)
  8. Tool view: is it clear that its chat edits the object and is separate from the conversation? Is the small card in the conversation (type · subject, Edit draft; Open form only in the tool) enough?
  9. Tool view: should it open by itself when the draft starts (as here), or only from Edit draft?
  10. Split: are the starting widths right (form 40%, graph 70% with the conversation hidden)? Should a width the user drags to be remembered per tool?
  11. Graph with the conversation hidden: does it feel like today's maximize dialog, so it can replace it?
  12. Editing a value in place: discoverable enough (hover tint, text cursor), or does it need a pencil icon?
  13. Phone width: the fields stack under their labels.
